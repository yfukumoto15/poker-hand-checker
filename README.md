# ポーカーハンドチェッカー

## 概要
手札5枚を入力すると、ポーカーの役を自動判定します。

## Webアプリの使い方
- ローカルで `http://localhost:3000/` にアクセス
- 手札を「スート＋数字」形式でスペース区切りで入力（例: `S10 S11 S12 S13 SA`）
- 入力例：
  - `S10 S11 S12 S13 SA`（スペードの10, 11, 12, 13, A）
  - `H10 H11 H12 H13 HA`（ハートの10, 11, 12, 13, A）
  - `C2 C3 C4 C5 C6`（クラブの2, 3, 4, 5, 6）
- 区切りは**半角スペースのみ**対応しています（全角スペースやカンマ不可）
- 入力が空、または空白だけの場合もエラーが表示されます
- 判定結果やエラーメッセージは画面下部に表示されます

## 入力仕様
- スート: S（スペード）, H（ハート）, D（ダイヤ）, C（クラブ）
- 数字: A, K, Q, J, 10, 9, ..., 2
- 入力例: `S10`（スペードの10）, `H3`（ハートの3）, `D12`（ダイヤの12）, `C2`（クラブの2）
- 区切り: **半角スペースのみ**
- 5枚ちょうど入力してください

## バリデーション・エラー例
- 「カードが5枚ではありません」
- 「不正なカードがあります: P1, 1C」
- 「重複しているカードがあります」
- 「入力がありません。手札5枚を入力してください」
- 「カードの区切りは半角スペースのみ対応しています」
- 複数のエラーがある場合はすべて表示されます

## APIエンドポイント
- URL: `http://localhost:3000/api/v1/check`
- メソッド: `POST`
- Content-Type: `application/json`
- リクエスト例:
  ```json
  { "cards": [
    "S10 S11 S12 S13 SA",
    "H9 H10 HJ HQ HK"
  ] }
  ```
- レスポンス例:
  ```json
  {
    "result": [
      { "card": "S10 S11 S12 S13 SA", "hand": "ロイヤルストレートフラッシュ", "best": true },
      { "card": "H9 H10 HJ HQ HK", "hand": "ストレートフラッシュ", "best": false }
    ]
  }
  ```
- best: true の手札が複数ある場合（同じ役の場合）は全てbest: trueになります。
- エラー時レスポンス例:
  ```json
  {
    "errors": [
      { "card": "S10 S10 SQ SK SA", "errors": ["重複しているカードがあります"] }
    ]
  }
  ```

## 注意事項
- 全角スペースやカンマ区切り、前後に余計な空白がある場合はエラーになります
- 入力例をコピペしてもエラーにならないように設計されています
- 画面・APIともにバリデーションエラーは必ず表示・返却されます

## 設計・実装方針（ベスト判定の実装背景）

本アプリでは、APIで複数手札を受け取り、その中で最も強い役（best: true）を持つ手札を判定する機能を実装しています。

### なぜ「コントローラー内で直接best判定」を選択したか
- 現状のアプリ規模・要件では、役判定ロジックはサービス層（PokerHandChecker）に集約し、API側で複数手札・best判定をまとめて処理することで、シンプルかつ柔軟な実装が可能です。
- 仕様変更（best判定の条件追加やレスポンス形式の変更など）にもAPI層で完結しやすく、現時点ではサービス層の肥大化や分割の必要性が低いと判断しました。
- 今後、役判定ロジックの再利用や他用途でのbest判定が必要になった場合は、サービス層の分割やリファクタリングも検討しやすいバランスの取れた構成です。

### 他の選択肢と比較した特徴
- サービス層にbest判定まで含める方法もありますが、現状はAPI層での柔軟な制御・シンプルさを優先しました。
- サービス層を役判定用・best判定用に分割する方法もありますが、小規模なアプリではやや複雑になりすぎるため、現時点では採用していません。
